# Metten desktop package

## Overview

This package hosts the Mac window, connects screen requests to the Rust engine,
and contains the isolated dummy credential proof. The engine owns session state
and recording; the screen requests actions and displays returned state. The
[product specification](../METTEN_DESIGN_DRAFT_2026-11-12.md) and
[ADR 0001](../docs/adr/0001-rust-engine-and-tauri-boundaries.md) define the intended
boundary. The documented session is a controlled, non-trading integration proof.

This contract covers the foundation and issue #3 credential behavior. Issue #4
work in the working tree, including its command and permission additions in
shared files, is deliberately excluded. The three commands below describe this
bounded contract, rather than an exhaustive listing of the unfinished tree.

## Interface

| File or group | Contract |
| --- | --- |
| [src/](./src/README.md) | `main.rs:Workspace`, `snapshot`, `control`, `credential`, and `begin_quit` bridge screen requests, engine state, credential work, and shutdown. `credential.rs:Credentials` implements the dummy-only native adapter. |
| [Cargo.toml](./Cargo.toml) | Package `metten`, Rust 2024 with minimum Rust 1.100; depends on the local `metten-engine` and Tauri. Mac-only Core Foundation, Security bindings, libc, and Serde support the native credential adapter. `tauri-build` supplies the build manifest. |
| [build.rs](./build.rs) | `main` calls `tauri_build::try_build` with an app-command manifest. The in-scope command entries are `snapshot`, `control`, and `credential`; generated permission files correspond to those entries. |
| [tauri.conf.json](./tauri.conf.json) | `identifier` is `com.metten.foundation`; `app.windows` defines the `main` window. `build` connects the Vite development URL and production `../dist` assets. `bundle` targets a Mac `.app`, minimum macOS 11.0, using the two packaged icons. |
| [capabilities/main.json](./capabilities/main.json) | Capability `main` selects the `main` window. In-scope grants are `allow-snapshot`, `allow-control`, and `allow-credential`. There are no filesystem, SQL, shell, or network plugin grants. |
| [permissions/autogenerated/snapshot.toml](./permissions/autogenerated/snapshot.toml), [control.toml](./permissions/autogenerated/control.toml), [credential.toml](./permissions/autogenerated/credential.toml) | Generated `allow-*` and `deny-*` command permission declarations. They do not add input validation; the Rust command boundary does that. These files identify themselves as generated and must not be hand-edited. |
| [icons/icon.icns](./icons/icon.icns), [icons/icon.png](./icons/icon.png) | Bundle icon assets selected by `bundle.icon`; the PNG is 512 × 512 RGBA and the ICNS is its Mac packaging asset. |

Generated `gen/` schemas are ignored build output, not maintained source contracts.
The root [package.json](../package.json) provides the frontend and Tauri commands;
the [Cargo workspace](../Cargo.toml) includes this package and the engine.

## Invariants

- `main.rs:main` selects storage natively through `app_data_dir()` or the native
  `METTEN_TEST_WORKSPACE` environment override, then opens `session.sqlite` with
  `Engine::open`. No in-scope screen command accepts a workspace path or SQL.
- `tauri.conf.json:app.security.csp` restricts production content to local assets
  and IPC connections, with no object loading, base override, or form submission.
  `main.rs:permissions_tests::app_commands_are_limited_to_the_local_main_window`
  checks local-main access and refusal of other-window and remote origins, plus
  an invented `read_secret` command.
- `main.rs:decode_credential` accepts only the supported operation/value shape and
  returns a fixed error for malformed requests. `credential.rs:Credentials`
  accepts bounded dummy values and a runner-selected disposable Keychain, not
  ordinary provider credentials. Native local comparison never returns bytes to
  the screen.
- `main.rs:begin_quit` waits for active credential work and the engine's saved
  stopped boundary before successful exit. A failed save keeps the application
  open and exposes the failure through `snapshot`.

## Side Effects

- `main.rs:main` creates the native-selected workspace directory and opens the
  engine, which owns SQLite writing and its workspace lock. Desktop code does not
  perform SQL itself.
- `credential.rs:Credentials::setup` can unlock only the explicitly bootstrapped
  disposable Keychain. `Credentials::execute` can add, update, remove, or read
  the fixed dummy item through native Security APIs; macOS may display access
  prompts. Normal launches have no credential target and refuse these actions.
- `main.rs:begin_quit` starts blocking shutdown work, may show/focus the window
  after a save failure, and calls `app.exit(0)` only when ready. Build commands
  generate assets, schemas, permissions, and bundle output.

## Verification

From the repository root, the configured checks include `cargo test -p metten
--locked`, `cargo test --workspace --locked`, `npm run check`, and `npm run tauri
build -- --bundles app`. The [CI workflow](../.github/workflows/checks.yml) also
checks formatting, Clippy, and the credential runner's process regression.

The latest finished section of [issue #3's evidence](../docs/verification/issue-3.md)
records a passing unchanged local ad-hoc-signed arm64 bundle: native add/read/
replace/delete, locked and unavailable refusal, actual access-prompt denial,
guarded quit during a pending prompt, secret-marker scans, and cleanup. Its older
checkpoints are historical. [Issue #2's record](../docs/verification/issue-2.md)
supplies foundation and recording evidence; its old pending-CI wording does not
establish current tracker status.

These README additions were checked against source and their links were checked;
no app, build, test, Keychain operation, or account access was run for this
documentation task. Earlier bundle evidence covers the recorded version and
unchanged behavior, not the unfinished issue #4 tree. Distribution signing,
notarization, upgrade identity continuity, other Macs, power-loss durability,
runtime compromise protection, future exports/backups, and trading remain outside
that proof. The credential adapter uses deprecated file-Keychain lifecycle APIs.
