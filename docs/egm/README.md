# EGM baseline outside issue #4

## Overview

This is the entry point for repository-wide documentation drift checks **outside issue #4**. Established 13 November 2026 for [issue #26](https://github.com/moultonlavah/metten/issues/26), against foundation commit `b1eb58c25fed5a2970bd5c40db9c05f673ff8d71` and the unchanged non-#4 portions of the working copy. It documents existing behavior, not retrospective approval of every implementation choice.

The [product specification](../../METTEN_DESIGN_DRAFT_2026-11-12.md) and accepted ADRs remain authoritative. Closed issues #1–#3 supply completed-slice context: MIT licensing, a controlled persisted session, and isolated dummy-credential integration. Later product features remain planned; their absence is not a regression in those completed slices. GitHub owns current issue status; historical verification records are not a second tracker.

### Explicit issue #4 exclusions

Do not inspect, edit, validate, approve or report drift on `docs/proposals/`, `examples/learning.json`, `crates/engine/src/strategy.rs`, `crates/engine/tests/strategy.rs`, or `src-tauri/permissions/autogenerated/strategies.toml` for this baseline.

Shared files also contain issue #4 work. Exclude its additions in:

- `crates/engine/Cargo.toml`, `crates/engine/src/lib.rs`, `crates/engine/src/storage.rs`: strategy dependency/module/APIs, recorder-sharing changes and strategy persistence/schema changes.
- `src-tauri/src/main.rs`, `src-tauri/build.rs`, `src-tauri/capabilities/main.json`: strategy command, registration and permission changes.
- `index.html`, `src/contract.ts`, `src/main.ts`, `src/style.css`: strategy import UI, types, handlers and styles.

Use the foundation commit and the current diff to distinguish those portions. The ten mixed files were already modified when this baseline started; no claim is made about the complete current schema, dependency surface or command set. New issue #4 files may appear later: classify them as excluded rather than silently incorporating them. Changes whose ownership cannot be established are an unresolved coverage gap, not a clean result. Issue #4 can be added only under a separately authorized scope.

### Other exclusions

Ignored private research/planning and runtime data, credentials, `.git/`, dependency installations, generated `src-tauri/gen/`, `target/`, `dist/`, `.scratch/` and temporary verifier resources are not maintained implementation inputs. Follow `.gitignore`; do not read secret/private records to perform drift reporting. Include hidden maintained configuration such as `.github/` and `.gitignore` in the coverage check.

## Invariants

- Trace each in-scope component to a contract and compare in both directions: documented behavior versus current code, and code versus documentation coverage. A new undocumented file or behavior is a finding even if the existing contracts still match.
- Source-grounded observations do not override the product specification, accepted ADRs or issue acceptance criteria. Record contradictions rather than blessing current code by copying it into a README.
- Preserve the distinction between effective control, accepted requests and confirmed saved state; dummy credential proof is not real account/provider integration. No paper/live behavior or release readiness is established here.
- Historical records retain original results and limitations. Later finished checkpoints supersede earlier incomplete states; old CI wording is not current remote status. No fresh test result is implied by a source inspection.

## Side Effects

Drift checking reads source and writes a dated Markdown report. It does not modify source, issue #4 artifacts, credentials, runtime state, requirements or the inspected contracts. Fixing a discrepancy is separate bounded work. No scheduled job or new dependency is required.

### Repeatable drift-report request

Select `egm-drift-report` and supply this request:

```text
EGM artifact directory: docs/egm

Run a read-only drift check in this repository using docs/egm/README.md
as the coverage map. Read the linked component contracts and the product
specification/accepted ADRs with the implementation-stage context recorded
there. Compare every in-scope component with current source and compare the
maintained-file inventory back to documentation, including tests, config,
build/CI and static asset ownership. Report uncovered logic explicitly.

Exclude issue #4 exactly as documented, including its portions of shared
files. Do not inspect or change its implementation or planning artifacts.
Future features are planned work, not completed-scope regressions. Treat
historical verification as historical evidence, not current status.

Write docs/egm/YYYY-MM-DD_DRIFT_REPORT.md with a section per inspected
contract and specific discrepancies only (or No drift detected). State scope,
coverage gaps and verification limits. Do not fix source or rewrite contracts
in this reporting pass. If today's report exists, append a clearly identified
new pass rather than overwriting prior findings.
```

Run periodically (weekly is a reasonable manual cadence) and update the owning contract whenever an authorized implementation change changes its behavior. Reconcile new maintained files with the inventory before calling a report complete.
