# Domain documentation

This is a single-context project: `GLOSSARY.md` at the root and `docs/adr/` for decisions.

Before exploring implementation, read the glossary and ADRs relevant to the change. If a referenced domain document does not exist, continue without creating empty scaffolding. Use the glossary's terms consistently in issues, code and explanations.

An ADR conflict must be surfaced explicitly before changing the decision. Add glossary entries only when terms are resolved; keep implementation details out of the glossary. Create an ADR only for a consequential tradeoff that future maintainers need to understand.
