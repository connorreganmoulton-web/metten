# Metten Gen 1 implementation plan

This approved breakdown is tracked in GitHub Issues. The product specification and ADR 0001 remain authoritative. Issue links and native blocking relationships identify the work sequence. Publishing a ticket does not start implementation or authorize trading. GitHub labels describe readiness of the brief, not permission to act on blocked work or access credentials.

Each implementation ticket includes relevant UI, storage, tests and documentation for the behavior it introduces. Earlier slices are developer proofs, not public trading releases; production submission remains unavailable until the integration and release gates are satisfied. Tests should primarily exercise the engine's public controls with controlled clock/source/execution inputs; packaged UI, Keychain and exchange contracts receive focused integration checks. This is the agreed test surface for the planned work.

Engineering owns routine interface and schema details. Do not invent D/F strategies, import old-bot code, or add unrelated markets/features. Live account access, paid services and real-money actions need exact separate authority. All intermediate evidence must be labeled honestly.

GitHub issue bodies own the acceptance criteria and current status. This document is an index, not a second task tracker.
