**B9-2 — Major: bounded native strategy work lacks a defined admission mechanism.**

Affected design: lines `464–477`, `494`, `520–526`, and `646`.

Source evidence:

- `src-tauri/src/main.rs:45–62` starts a new `tauri::async_runtime::spawn_blocking` task for each strategy invocation.
- `crates/engine/src/lib.rs:313–325` serializes imports/listing through the same recorder mutex that the controlled-session recording worker acquires at `lib.rs:176`.
- The existing implementation has no native strategy-operation concurrency or pending-request limit. Disabling frontend buttons does not constrain direct IPC requests.
- The installed Tauri runtime delegates blocking work to Tokio (`tauri-2.12.5/src/async_runtime.rs:209–215,310–317`). That mechanism supplies execution threads; it does not establish the proposed application-level admission bound.
- Item 6 limits individual documents, responses and evaluator evidence, but gives no limit or refusal behavior for concurrently queued preview/save/list/detail requests. Merely retaining the current blocking pattern leaves multiple bounded payloads and tasks able to accumulate while waiting for the shared recorder.

Smallest correction: specify one native in-flight strategy operation, acquired nonblockingly **before** spawning blocking work, with a finite Busy response for additional requests and guaranteed release on completion/failure. Keep the quit check and add a focused direct-IPC admission/recovery check alongside the planned native tests. This fits the already allowed `src-tauri/src/main.rs`; it needs no dependency or broader architecture change. An equally concrete bounded alternative would also resolve the finding, but the implementer should not have to choose it.
